# 验收检查清单（主管交付前）· Acceptance checklist

> 通用清单，再按场景补 2–4 条专属项（见各场景 README）。
> Generic checklist; add 2–4 scenario-specific items.

通用清单，再按场景补 2–4 条专属项：

- [ ] 文件存在，路径与派活消息一致
- [ ] 逐条对照验收标准，未满足项写明原因
- [ ] 事实、数字有来源，或已标注【待核实】
- [ ] 对外内容（邮件、帖子、消息）仍是草稿，没有被发送或发布
- [ ] 没有越过用户设定的红线（价格、付款、交易、删除、承诺）
- [ ] 不合格时附具体意见退回；两轮仍不达标，向用户说明情况

## 场景专属项示例

- **🎬 内容创作者**：文件存在且路径与派活消息一致（[更多](../scenarios/creator/README.md)）
- **🛠️ AI Builder**：PR 链接可打开，CI/测试结果为通过（[更多](../scenarios/builder/README.md)）
- **🏪 小企业主**：表格可打开、列名完整、合计核对无误（[更多](../scenarios/smb/README.md)）
- **💼 自由职业者/咨询师**：结构与派活要求一致，字数在范围内（[更多](../scenarios/freelancer/README.md)）
- **🛒 电商卖家**：数字与原始数据文件一致（抽查）（[更多](../scenarios/ecom/README.md)）
- **🎓 学生/研究者**：抽查 3 篇文献，出处真实可查（[更多](../scenarios/research/README.md)）
- **📈 投资者/交易员**：每个数字都有来源与期间（[更多](../scenarios/invest/README.md)）
- **🤝 销售/市场营销**：对外邮件和 Slack 消息都只是草稿，没有被发送（[更多](../scenarios/sales/README.md)）
