# 一个人，一支 Bot 团队：8 种身份的 Grok Bot 多 bot 实战手册

> 你不需要一个更聪明的助手，你需要一支会分工、会交接、会验收的团队。

很多人用 AI 助手的方式是：一个对话框，什么都往里塞。写稿、回邮件、查资料、做表格……结果上下文越来越乱，输出越来越不稳定。

换个思路：**让一个主管 bot 当你的唯一入口，下面配几个各司其职的专员 bot。**你只提需求、做关键决定，剩下的交给团队。

这篇把完整的方法和 8 种用户类型的团队配置都整理好了，提示词可以直接拿去用。

---

## 先说清楚：Grok Bot 的多 bot 是什么

Grok Bot 可以同时运行多个助手 bot：每个 bot 有自己的对话、描述提示词（人设）、记忆、定时例行任务和连接的工具（如 Gmail、Calendar、Slack、GitHub、X、Notion）。

所有 bot 共用同一台云电脑（文件共享），但各自拥有独立的桌面和浏览器，并且可以互相发消息。

本手册按 8 种用户类型，给出可直接复制的团队配置与提示词。

---

## 推荐模式：一个主管 + 若干专员

1. 你把需求发给「主管」
2. 主管拆解任务，发消息派给专员（写明交付物与验收标准）
3. 专员完成后存到 `/workspace/shared/<名称>/` 并把路径回报主管
4. 主管打开文件核对验收标准
5. 合格后交付给你

好处：你只需对接一个入口；每个专员的提示词、记忆和工具保持聚焦；所有产出都落在共享文件夹里，可追溯、可复用。

## 提示词一般写什么

bot 的描述提示词决定它“是谁、做什么、怎么做”。一份好的提示词通常包含以下 7 个部分，本手册里每个 bot 的提示词都按这个结构写成，可直接复制再按需改动。

**① 角色定位**
一句话说清它是谁、服务谁、核心目标是什么。
> 你是「选题研究员」，为一位科技类视频博主寻找有传播潜力的选题。

**② 任务范围与边界**
列出负责的事，也列出明确不做的事（例如不代发邮件、不做付款、不发布内容）。边界能防止越权和误操作。
> 只做研究与建议；不发帖、不回复他人。

**③ 输出格式**
规定交付物长什么样：文件类型、结构、字数、表格列、命名规则和保存路径。格式越具体，越容易验收。
> Markdown 表格：选题 | 依据链接 | 热度判断 | 建议角度。

**④ 语气**
对用户/对外写作时的风格：简洁还是详细、正式还是口语、是否用表情等。
> 结论先行，口语化但专业，不堆砌形容词。

**⑤ 工作流程**
按步骤写出它该怎么做：先查什么、如何筛选、如何自检，可以减少遗漏，结果更稳定。
> 1. 扫描 → 2. 去重 → 3. 打分 → 4. 自检 → 5. 存档并回报。

**⑥ 何时询问用户**
写清楚哪些情况必须先确认：涉及对外发送、花钱、删除、信息不足或存在多种合理理解时。
> 任何对外发送的内容，先给草稿，等用户确认。

**⑦ 与其他 bot 的协作**
它的主管是谁、要和谁配合、文件存哪里、完成后回报什么。主管的提示词还要写明团队成员和派活规则。
> 成果存到 /workspace/shared/creator/research/，完成后把路径和摘要发给「内容主管」。

小提示：用户确认过的长期偏好（如固定格式、常用语气、客户名单）可以让 bot 记入记忆，而不必每次重复；但核心规则仍应写在提示词里。

## 团队怎么“接力”：派活、回报、共享文件夹

8 个场景用的是同一套协作机制，先看懂它。

**派活消息必须包含 6 项：**任务、背景、交付物、验收标准、截止时间、保存路径。一条消息只派一个任务。

**专员回报包含 4 项：**文件路径、3 行以内摘要、逐条自检结果、未解决的问题。

**共享文件夹约定：**
- 每个团队一个根目录 `/workspace/shared/<名称>/`，每个 bot 一个子文件夹
- 文件名统一为 `YYYY-MM-DD-简短任务名`
- 每个 bot 只写自己的子文件夹，读取别人的产出但不修改
- 原始资料只读，处理结果另存新文件

**主管验收：**打开文件逐条核对；不合格附具体意见退回；两轮仍不达标，向你说明情况。

## 场景 1：🎬 内容创作者

适合博主、视频作者、新媒体编辑。把“找选题 → 写稿 → 多平台分发 → 数据复盘”拆给不同专员，你只需要确认选题和终稿。

**团队配置**
- **内容主管**（主管）：接收内容需求，拆解派活，维护排期，验收后交付终稿和发布建议
- **选题研究员**：追踪 X 热点和同类创作者，产出带依据的选题清单
- **脚本撰稿人**：按已确认选题写长文、视频脚本、标题和封面文案
- **分发运营**：改写多平台版本，汇总 X 帖子表现，筛选合作邮件并起草回复

**怎么串起来**
研究员每天 07:30 扫描 X 出候选选题 → 主管 08:30 汇总给你确认 → 撰稿人按确认的选题出初稿 → 分发运营改写成各平台版本、只出草稿 → 你确认后发布。

**提示词片段（选题研究员）**
> 你是「选题研究员」，一位内容创作者的选题研究员，负责发现有传播潜力、且与账号定位相符的选题。
> 边界：不发帖、不点赞、不回复任何人；不编造数据，拿不到的数据写“未知”。
> 工作流程：收集候选信息并保留来源链接 → 去重 → 按“相关度、时效性、差异化”各 1–5 分打分 → 自检：每个选题都有来源链接和建议角度。

## 场景 2：🛠️ AI Builder

适合独立开发者和小型 AI 产品团队。主管像技术负责人兼产品经理；所有 bot 共用一台云电脑，代码和产出在共享目录中流转。

**团队配置**
- **技术主管**（主管）：把需求和 bug 拆成任务，排优先级，派活验收，汇报进展与风险
- **编码工程师**：在云电脑上实现功能、修 bug、跑测试，提交分支和 PR
- **代码审查员**：审查 PR 的正确性与安全性，补测试，给出审查意见
- **AI 研究员**：跟踪模型、框架、论文动态，做技术选型对比
- **文档与发布**：维护 README，生成 changelog，起草发布帖子

**怎么串起来**
主管每个工作日 09:00 汇总 GitHub 新 Issue 和待审 PR → 派给编码工程师 → 编码工程师提 PR 并回报测试结果 → 代码审查员二次检查 → 合并由你决定 → 文档与发布根据已合并 PR 写 changelog。

**提示词片段（编码工程师）**
> 你是「编码工程师」，一个 AI 产品团队的编码工程师，负责把任务变成可运行、有测试的代码。
> 边界：不直接推送到主分支，不强制推送；不修改与任务无关的文件；不把密钥、令牌写进代码或日志。
> 输出格式：PR 描述：背景 | 改动 | 测试方式 | 风险。

## 场景 3：🏪 小企业主

适合门店、工作室、小团队老板。主管像总经理助理，每天给你一份晨报；所有对外邮件和付款类事项都只出草稿，由你拍板。

**团队配置**
- **总经理助理**（主管）：统一入口，整理日程和重要邮件，每日晨报，分派任务
- **客服专员**：分类客户咨询邮件，按 FAQ 起草回复，维护问题库
- **财务助理**：整理发票账单，维护收支表，提醒应收应付
- **营销助理**：策划促销，撰写社媒和邮件营销文案，关注同行动态

**怎么串起来**
客服专员一天三次处理新咨询、生成草稿 → 财务助理每周五出应收应付提醒 → 营销助理每周一出社媒草稿 → 总经理助理每个工作日 08:00 汇总成晨报，“需要你决定”的事放最前面，最多 3 项。

**提示词片段（总经理助理）**
> 你是「总经理助理」，一位小企业主的总经理助理，目标是让老板每天只需处理最重要的决定。
> 边界：不代替老板发送对外邮件或接受会议邀请；不进行任何付款、转账或下单；不删除邮件和日程。
> 输出格式：晨报格式：① 需要你决定（≤3 项）② 今日日程 ③ 重要邮件摘要 ④ 专员进度。

## 场景 4：💼 自由职业者/咨询师

适合独立顾问、设计师、自由撰稿人等一人公司。三个专员覆盖“找客户 → 做项目 → 收款”的完整闭环。

**团队配置**
- **业务主管**（主管）：管理客户、项目和日程，确保按时交付、按时收款
- **拓客助理**：研究潜在客户，写个性化外联草稿，跟进未回复线索
- **交付助理**：起草方案、报告、演示大纲，整理会议纪要与行动项
- **账务助理**：起草报价单和发票，追踪付款，起草催款邮件

**怎么串起来**
每个客户一个子文件夹，所有专员从同一处读背景 → 拓客助理每周二出 10 个线索和外联草稿 → 交付助理每天整理会议纪要 → 账务助理每周一列出逾期发票和催款草稿 → 业务主管汇总成项目看板。

**提示词片段（拓客助理）**
> 你是「拓客助理」，一位独立顾问的拓客助理，帮顾问稳定地获得高质量线索。
> 工作流程：为每个线索写 1 个具体的切入点（近期动态、痛点）→ 起草不超过 120 字的外联邮件 → 自检：信息有来源、邮件个性化而非模板化。
> 语气：真诚、具体、不推销腔。

## 场景 5：🛒 电商卖家

适合独立站和平台卖家。店铺后台数据以导出文件的方式放进共享文件夹，由数据分析员处理，主管整合成每日经营简报。

**团队配置**
- **店铺主管**（主管）：统筹选品、上新、客服与数据，每日经营简报
- **选品分析师**：研究竞品价格、新品和趋势，评估候选商品
- **商品文案**：撰写标题、卖点、详情页和多语言版本
- **客服专员**：分类售后邮件，起草回复，汇总高频问题
- **数据分析员**：处理订单、流量导出文件，生成日报和专题分析

**怎么串起来**
你把导出文件按固定文件名放进 `/workspace/shared/ecom/data/` → 数据分析员 08:00 出日报 → 店铺主管 08:30 汇总成“数据 → 洞察 → 建议动作”。上新走流水线：选品 → 文案 → 主管验收 → 你确认。客服汇总的高频问题回流给商品文案改详情页。

**提示词片段（数据分析员）**
> 你是「数据分析员」，一家电商店铺的数据分析员，把原始数据变成可执行的结论。
> 边界：不修改原始数据文件，处理结果另存；不推测缺失的数据。
> 工作流程：检查文件是否为最新、字段是否完整 → 计算核心指标 → 与前一期对比 → 自检：抽查 3 条原始记录，确认汇总正确。

## 场景 6：🎓 学生/研究者

适合本科生、研究生和科研人员。文献、写作、数据三位专员分工协作；写作助理只提供结构与修改建议，帮助你遵守学术诚信。

**团队配置**
- **研究主管**（主管）：拆分课题阶段，管理截止日期和每周计划
- **文献研究员**：检索筛选文献，写结构化摘要，维护文献表
- **写作助理**：给出结构、逻辑、语言和引用格式建议
- **数据分析员**：清洗数据、统计分析、作图，保存可复现代码

**怎么串起来**
研究主管从截止日期倒排里程碑，每周日生成下周计划 → 文献研究员维护一份所有人共用的文献表 → 数据分析员产出可复现的结果 → 写作助理每周五对新草稿给修改意见 → 主管验收时抽查文献出处。

**提示词片段（文献研究员）**
> 你是「文献研究员」，一位研究者的文献研究员，帮助快速、准确地掌握领域进展。
> 边界：不编造文献、作者、年份或引用；无法确认的标注【未核实】；不替用户写需要独立完成的综述正文。
> 输出格式：文献表：标题 | 作者 | 年份 | 出处/链接 | 研究问题 | 方法 | 主要发现 | 与本课题关系。

## 场景 7：📈 投资者/交易员

适合个人投资者和交易员。团队只做信息收集、研究与复盘，不执行任何交易。

**团队配置**
- **投研主管**（主管）：统筹情报、研究、复盘，输出投研简报
- **市场情报员**：监控 X 和新闻中与观察清单相关的动态
- **研究分析师**：读公开财报，建财务表与同业对比，写研究笔记
- **风控复盘员**：根据你放入的交易记录复盘，检查是否遵守你自己的规则

**怎么串起来**
市场情报员 07:30 收集隔夜动态 → 投研主管 08:00 出盘前简报 → 研究分析师在财报季准备要点清单 → 风控复盘员每周五对照你写下的交易规则逐条检查。每条信息都带来源和时间。

**提示词片段（投研主管）**
> 你是「投研主管」，一位个人投资者的投研主管，目标是让用户基于完整、及时、可核实的信息做决策。
> 边界：不执行、不建议具体下单操作和仓位数量；不登录任何券商或交易账户；不把内容表述为确定性的投资建议。
> 输出格式：要点 3–5 条 → 关注标的动态表 → 风险与反方观点 → 待你判断的问题。

（投资相关内容仅为信息整理，不构成投资建议。）

## 场景 8：🤝 销售/市场营销

适合销售、客户经理、BD 和市场营销人员，以及自己经营生意、管理客户的人。主管帮你盯住所有客户和单子（pipeline），所有对外邮件和消息都只出草稿。

**团队配置**
- **销售主管**（主管）：管理客户名单和单子看板，统筹会前准备、跟进和 pipeline 复盘
- **客户研究员**：研究客户公司、关键人和动态，整理客户档案与切入话题
- **会议参谋**：准备会议简报、提问清单、异议应对和谈判方案
- **跟进助理**：整理会议纪要，起草跟进邮件和 Slack 消息草稿，提醒久未跟进的客户
- **管道分析员**：复盘 pipeline：阶段分布、停滞单、赢单率与推进优先级

**怎么串起来**
每个客户一个子文件夹（档案、往来要点、报价规则与底线）→ 客户研究员 07:30 为今明两天有会的客户更新档案 → 会议参谋每天 18:00 读取明天的日历，出一页会议简报 → 会后跟进助理整理纪要、起草跟进邮件 → 管道分析员每周一复盘单子清单 → 销售主管每天告诉你今天该推进哪几单。

**提示词片段（会议参谋）**
> 你是「会议参谋」，一位销售人员的会议与谈判参谋，帮助用户带着清晰目标和充分准备走进每一场客户会议。
> 边界：不替用户参会，不接受或修改会议邀请；不自行设定价格底线——底线以用户提供的为准。
> 输出格式：谈判准备包：目标 | 底线 | 可让步项（按顺序）| 不可让步项 | 替代方案。

## 最后：三条通用原则

**1. 你只守关键节点。**选题、终稿、报价、合并、下单……只在这些节点介入，其他交给主管推进。

**2. 草稿制度。**涉及对外发送、付款、交易、删除等操作时，始终让 bot 先出草稿、由你确认。

**3. 让例行任务替你坚持。**专员先跑、主管汇总，晨报和周报按时到。例行时间均为示例，请按你的时区和作息调整。

从一个场景开始，先搭一个主管 + 两个专员，跑顺了再加人。你的第一支 Bot 团队，今天就能上岗。
